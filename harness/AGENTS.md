# Host-harness routing

This boundary will contain host conformance evidence: Web Platform Tests
replayed against the pinned reference implementation, Node's
`node:stream/web`, and Bun, plus decision-tape replay of the bounded Lean
runner against those hosts. Host evidence tests an exact host profile; it does
not own Whatwg semantics.

## Exact profiles

Every harness records the vendored specification commit, the reference
implementation bytes, the WPT commit, the host runtime name and version, the
platform, and the command it exercised. A result under one host is evidence
about that host profile only. Browser engines enter only through published
WPT results, cited by run identifier, and never as a local claim.

Generated programs are inputs to independent execution, not self-validating
evidence. Positive, negative, and mutation cases remain separate. Runtime
observations state their decision tape, the observation mask they were
compared under, and every ambient assumption needed for replay.

## Routing results

Semantic counterexamples receive stable IDs in
`test/counterexamples/REGISTER.md`; their host fixtures live in the relevant
harness area and are linked from that row. A host that diverges from the
specification is recorded as a host-profile refusal row, never as a change to
the model.

Deterministic reports and coverage projections belong under `generated/` and
are regenerated by a recorded command. Caches, installed dependencies,
transient logs, and machine-specific paths are not canonical evidence.

A target proof-graph edge closes only when all evidence named by that edge is
present. A WPT pass cannot close a Lean simulation theorem.
